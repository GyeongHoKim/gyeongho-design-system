Add `NavMenu` (`@ghds/react/nav-menu`) and `<gh-nav-menu>` (`@ghds/web-components/nav-menu`): a hand-drawn dropdown for grouped site navigation. A `<button aria-expanded aria-controls>` trigger shows a floating panel holding a plain `<ul>` of real `<a href>` links, so entries keep native link behaviour (open in new tab, copy link address, crawlability). Unlike `Menu` / `gh-menu`, it uses no `role="menu"` / `role="menuitem"` anywhere — it follows the ARIA disclosure-navigation pattern instead of the command-menu pattern. Props: `label` and `items: { href, label }[]` (a property on the web component). Links are in the natural Tab order; ArrowDown / ArrowUp on the trigger open the panel and focus the first / last link, Arrow / Home / End move between links, Escape closes and returns focus to the trigger, and clicking outside or tabbing out closes it. Pass `current` (the active page's path) to mark the page: the link whose `href` matches it exactly gets `aria-current="page"` (bold and underlined), and the trigger label is underlined when any link is the current path or an ancestor of it (`/components/` on `/components/button/`); query strings, hashes and trailing slashes are ignored, and hash- or query-only hrefs never match. It reuses the `comp.menu.*` tokens and the same floating-ui positioning as `Menu`, now shared through an internal helper.
