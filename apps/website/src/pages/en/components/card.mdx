## Overview

A `Card` is a generic surface for grouping related content — it isn't interactive by itself and
carries no built-in meaning beyond "these things belong together." On the web it can also be a
single link: see [Link cards](#link-cards).

## Anatomy

A sketchy rectangle outline drawn behind plain children. On Web Components, `gh-card` has two
slots: a named `title` slot rendered first, and the default slot for the body. Content in the
`title` slot, and any `<h1>`/`<h2>`/`<h3>` in the default slot, gets title styling (`::slotted`
CSS). React and React Native have no equivalent title slot — content is just plain children.

The one real variation is a **different prop per platform**, not a shared state: React's `fill`
(`'solid' | 'hachure'`) controls the fill pattern; Web Components and React Native instead expose
`elevated` (a boolean drop-shadow effect) — a genuinely different API, not a superset of React's.

## Paper variants

`variant` switches the surface to a paper look. `plain` is the default sketch outline; `sticky` is a
sticky note and `lined` is ruled paper. `tone` picks the paper colour, `fastener` adds a piece of
tape or a pin, and `tilt` rotates the card slightly. Tape and pin are decorative and hidden from
assistive technology.

- React Native has no `interactive` or link mode yet.
- React's `fill` and Web Components/React Native's `elevated` apply to `plain` only.
- React Native reads the values from the Restyle theme (`theme.card.*`), so a custom theme overrides them.

```tsx
// React
<Card variant="sticky" tone="warning" fastener="tape" tilt="left">
  <h3>Reminder</h3>
  <p>Water the plants.</p>
</Card>
```

### Customizing paper colours

On the web every value is a CSS custom property. Set it on a container that wraps the cards to
change the paper inside it. Don't set it on `:root`: the dark theme redeclares every
`--comp-card-*` property (on `[data-theme]` and, in OS dark mode, on `:root:not([data-theme])`), so
the override is lost there. For the same reason, keep the container inside any element that carries
`data-theme`.

```css
.notes {
  --comp-card-sticky-bg-warning: var(--sys-color-paper-info);
}
```

### Lined cards

The rule gap equals the body line box, so body text sits on the rules. This holds for body text
only: headings and element margins (such as the default `<p>` margins) shift the lines below them
off the rules. Fill a lined card with body text without extra margins, and don't change its
`line-height`.

## Link cards

To make the whole card one link, use `href` on Web Components or `asChild` with an `<a>` child on
React (the same pattern as Button's `asChild`). The link is the card surface itself, so there is no
wrapper element.

- On mouse hover the card lifts like `interactive`, and a `plain` card's sketch stroke darkens
  (`comp.card.stroke.hover`).
- On keyboard focus the card shows a focus ring (`comp.card.focus.ring`) and lifts.
- Paper variants, `tone`, `fastener` and `tilt` work as usual.

```tsx
// React
<Card asChild variant="sticky" tone="info">
  <a href="/docs/tokens">
    <h3>Tokens</h3>
    <p>Design values for every platform.</p>
  </a>
</Card>
```

```html
<!-- Web Components -->
<gh-card href="/docs/tokens" variant="sticky" tone="info">
  <h3 slot="title">Tokens</h3>
  <p>Design values for every platform.</p>
</gh-card>
```

Don't put buttons, inputs or other links inside a link card: interactive elements can't be nested
inside a link. The card's text content becomes the link's accessible name, so keep it short.

## Accessibility

- **React**: renders a plain `<div>`. No role or label is set automatically — "any ARIA role/
  landmark is the caller's to set" (per the component's own doc comment). With `asChild`, the
  child keeps its own semantics (for example a link).
- **Web Components**: when a `label` is supplied, `gh-card` automatically sets
  `internals.role = 'group'` and `internals.ariaLabel` — a real behavior React does *not* replicate.
  With `href`, the host has no role: the inner `<a>` is the link, and `label` becomes its
  `aria-label`, replacing the text content as the accessible name.
- **React Native**: sets `accessibilityRole="summary"` only when `accessibilityLabel` is passed.
- See the <a href={withBase('/accessibility/')}>Accessibility Guide</a> for general conventions.

## Content

N/A — Card has no fixed content model. Content is whatever the caller passes as children (React/RN)
or slots (Web Components).

## Code examples

```tsx
// React — @ghds/react (has `fill`, no `elevated`)
import { Card } from '@ghds/react/card';

<Card fill="hachure">
  <h3>Hachure</h3>
  <p>Sketched, translucent fill.</p>
</Card>;
```

```html
<!-- Web Components — @ghds/web-components (has `elevated` + `label`, no `fill`) -->
<script type="module">
  import '@ghds/web-components/card';
</script>
<gh-card label="Elevated" elevated>
  <h3 slot="title">Elevated</h3>
  <p>Drop-shadow sketch outline suggests elevation.</p>
</gh-card>
```

```tsx
// React Native — @ghds/react-native (has `elevated`, no `fill`)
import { Card } from '@ghds/react-native/card';
import { Text } from '@ghds/react-native/theme';

<Card elevated accessibilityLabel="Summary">
  <Text>Elevated card content</Text>
</Card>;
```
